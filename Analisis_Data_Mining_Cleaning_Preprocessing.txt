3. ALUR DATA MINING YANG DILAKUKAN

Alur yang digunakan adalah alur deskriptif yang menyerupai tahap data understanding -> data preparation -> EDA -> visualisasi -> interpretasi:

a. Memahami masalah dan kolom: menganalisis pesanan, kategori menu, harga, waktu tunggu, jarak, rating, promo, keluhan, dan status pesanan.
b. Memeriksa bentuk data, nama/tipe kolom, contoh baris, missing values, ID duplikat, format tanggal, rentang numerik, dan jumlah kategori.
c. Membersihkan dan menambahkan fitur turunan yang diperlukan.
d. Menghitung statistik deskriptif, distribusi kategori/status, agregat bulanan, dan korelasi.
e. Membuat enam visualisasi interaktif untuk menjawab enam pertanyaan analisis.
f. Menafsirkan pola dengan mencantumkan batasan data sintetis dan kualitas sumber.

Data mining di sini berarti menemukan pola deskriptif pada data. Ini bukan proses pelatihan model prediksi. Korelasi hanya menunjukkan asosiasi, bukan membuktikan sebab-akibat, walaupun pembuat dataset menyebut relasi tersebut sengaja ditanam dalam data sintetis.

4. DATA CLEANING DAN PREPROCESSING YANG BENAR-BENAR DITERAPKAN

Library utama: pandas.

a. Data sumber tidak ditimpa. Fungsi load_raw_data membaca CSV; clean_data membuat salinan untuk diproses.
b. Nama kolom dirapikan dengan strip. Spasi awal/akhir di beberapa kolom teks dibuang; string kosong pada kolom teks terkait diubah menjadi missing.
c. Baris dengan ID_Pesanan duplikat dibuang dengan keep='first'. Pada file aktual tidak ada duplikat, sehingga 8.500 baris tetap ada.
d. Waktu_Transaksi dikonversi ke datetime dengan format='mixed', dayfirst=True, dan errors='coerce'. Semua timestamp pada file saat ini berhasil diparse. Format tanggal yang berbeda disatukan sebagai tipe waktu, bukan dipakai untuk mengubah tanggal bisnisnya.
e. Harga_Pesanan, Jarak_Kirim_KM, Waktu_Tunggu_Menit, dan Rating_Pelanggan dikonversi menjadi numerik. Nilai rating di luar 1-5, jarak tidak positif, dan waktu tunggu negatif dijadikan missing.
f. Status_Promo dinormalisasi ke boolean untuk nilai true/false, 1/0, ya/tidak.
g. Missing values tidak diimputasi pada alur analisis deskriptif. Grafik memakai observasi yang tersedia untuk variabel terkait; misalnya scatter jarak hanya memakai baris yang memiliki jarak dan waktu tunggu.
h. Dibuat fitur turunan Bulan, Hari, dan Jam dari timestamp untuk tren dan heatmap.
i. Dihitung dua flag harga tanpa menghapus baris: aturan sumber Kaggle untuk harga <= 0 atau >Rp500.000, dan kandidat outlier IQR untuk harga positif >Rp85.250. KPI memakai aturan sumber; IQR dipakai untuk analisis sensitivitas.

5. AUDIT HARGA: IQR PROJECT VERSUS ATURAN YANG DIJELASKAN KAGGLE

Perhitungan pada harga positif:
- Q1 = Rp19.000
- Q3 = Rp45.500
- IQR = Q3 - Q1 = Rp26.500
- Batas atas = Q3 + 1,5 x IQR = Rp85.250

Hasil hitung aktual:
- 39 baris memiliki harga nol/tidak positif.
- 302 baris memiliki harga di atas Rp85.250.
- Implementasi saat ini menandai total 341 baris: 39 harga nol/tidak positif + 302 harga positif di atas batas IQR.
- Data Card menyebut 270 outlier buatan; hitungan CSV cocok tepat dengan aturan harga nol atau harga di atas Rp500.000: 39 + 231 = 270.
- Ada 71 harga pada rentang lebih dari Rp85.250 sampai dengan Rp500.000. Nilai ini ditandai oleh IQR, tetapi tidak termasuk hitungan 270 anomali yang secara eksplisit dijelaskan Data Card.
- Dengan aturan sumber Kaggle, KPI mencakup 7.338 pesanan selesai valid dengan total Rp243.363.500. Angka ini adalah metrik dataset, bukan pendapatan aktual.

Maknanya: angka 341 bukan kesalahan hitung; angka itu adalah hasil gabungan aturan statistik IQR dan harga tidak positif. Namun, angka tersebut berbeda dari 270 anomali yang dinyatakan Data Card. IQR menandai observasi untuk diperiksa, bukan membuktikan bahwa nilai tersebut salah. KPI final memakai aturan sumber Kaggle, sehingga 71 nilai antara Rp85.250-Rp500.000 tetap masuk KPI tetapi tetap tersedia sebagai kandidat untuk analisis sensitivitas.

REKOMENDASI: Simpan dua flag terpisah untuk transparansi:
1. Anomali yang dinyatakan pembuat data: harga <= 0 atau harga > Rp500.000 (270 baris pada file ini).
2. Kandidat outlier statistik: harga positif > Rp85.250 menurut pagar IQR (302 baris).

Laporkan total nilai pesanan dengan aturan yang dinyatakan eksplisit, lalu tampilkan analisis sensitivitas jika 71 kandidat tambahan IQR ikut dikecualikan. Jangan menghapus nilai secara otomatis sebelum memeriksa definisi domain dan maksud pembuat data.

8. APAKAH ADA METODE/TOOLS YANG LEBIH BAIK?

Tidak ada satu metode terbaik untuk semua tujuan. Pilihan harus mengikuti pertanyaan, asumsi, ukuran data, dan cara hasil akan dinilai.

A. Outlier harga
- IQR sesuai untuk flag awal karena robust terhadap skew dan mudah dijelaskan.
- Alternatif yang lebih tepat untuk menandai anomali buatan dataset ini adalah aturan domain dari Data Card: harga nol atau >Rp500.000. Aturan itu menghasilkan 270 baris dan cocok dengan keterangan sumber.
- Pilihan yang paling informatif adalah mempertahankan kedua flag (aturan domain dan IQR), membandingkan dampaknya pada KPI, lalu tidak menghapus data mentah.
- MAD/modified Z-score dapat menjadi pembanding robust lain. Z-score biasa kurang cocok bila distribusi harga sangat skew dan memiliki ekor ekstrem.
- IQR global tidak melihat kategori. Jika rentang harga normal tiap kategori memang berbeda, evaluasi juga batas per kategori dengan jumlah sampel memadai.

B. Missing values
- Membiarkan missing cocok untuk EDA deskriptif ketika nilai tidak diketahui dan imputasi berisiko menciptakan observasi palsu.
- Untuk model, imputasi median pada fitur numerik plus indikator missing dapat diuji dalam Pipeline scikit-learn; nilai imputasi harus dipelajari dari data latih saja untuk mencegah leakage.
- Rating kosong tidak sebaiknya otomatis diisi rating 3 jika rating menjadi target atau analisis kepuasan, karena itu mengubah distribusi outcome. Contoh Kaggle mengusulkan rating 3, tetapi itu hanya contoh, bukan aturan netral.
- Periksa apakah missing bersifat sistematis. Data Card menyebut pengguna yang malas memberi rating dan kegagalan GPS, sehingga missing mungkin tidak acak.

C. Tren waktu
- Moving Average bukan metode cleaning dan tidak menyelesaikan inkonsistensi kalender.
- Dengan hanya 12 titik bulanan dan ketidaksesuaian cakupan waktu, rolling average dapat menyamarkan anomali. Verifikasi tanggal dan versi dataset lebih penting.
- Setelah kalender tervalidasi dan tersedia riwayat lebih panjang, 3-month rolling average dapat ditambahkan sebagai garis bantu, sementara data aktual tetap ditampilkan.

D. Tools visualisasi
- Matplotlib/Seaborn baik untuk EDA statis dan laporan/notebook; kurang interaktif dibanding dashboard Plotly.
- Power BI/Tableau/Looker Studio dapat lebih baik jika prioritasnya drag-and-drop, distribusi dashboard ke pengguna bisnis, dan koneksi sumber data, tetapi mengurangi keterulangan analisis berbasis kode atau memerlukan lisensi/konfigurasi.
- Dash atau Bokeh memberi kontrol aplikasi web lebih besar, namun biasanya membutuhkan lebih banyak kode daripada Streamlit.
- Untuk tugas Python yang meminta grafik interaktif, Plotly + Streamlit adalah pilihan pragmatis, bukan satu-satunya pilihan terbaik.
